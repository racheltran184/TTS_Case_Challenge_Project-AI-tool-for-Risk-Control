Numbers and rules used by this tool

CASE = case data (Tables 1–5). DERIVED = arithmetic on case data, formula shown. EXTERNAL = a named published source. DECK RULE = a management rule from our solution deck (or marked tool rule), not a research finding.

What the tool does

  • Checks every completed hour against one fixed bar: target ÷ show hours.
  • Fires the deck's live-day warning when two hours in a row miss the bar.
  • Splits each hour into views, orders per 1,000 views and AOV, and names the weakest.
  • Shows only actions already written in the deck (Q3 funnel actions, Q4 shift control), each with its owner.
  • Tracks the four pre-live warning signals and the 14 Nov go / no-go gate.
  • Tracks cancellations and net GMV against the 11.11 rehearsal share.

What it deliberately does not do

  • No forecast, hourly shape or simulation: nothing in the case data supports one, so the plan is a straight line.
  • No 90% / 80% amber and red bands: no case data or research backs them. An hour passes or misses.
  • No AI hand-off. The rules run in code, so the same data always gives the same answer, and people decide.
  • No guessed values. Missing or skipped hours show as unknown, never as zero.

Guide

How to use Mission Control

One owner (TTS Ops) enters data. Everyone reads the same screen. The rules run in code, and people decide and log.

1. Set up once2. Before the live3. Every hour on 12.124. Read the screen5. When a signal fires6. Cancellations7. After the showData rules

1. Set up once

  1. Open Plan settings (left panel, Live day). Defaults are the deck values: USD 1M, 08:00–23:00, resets at 08:00, 13:00, 18:00, 5.1M views/h, 1.27 orders per 1,000 views, AOV $10.30.
  2. Do not tune the pass mark. It is always target ÷ show hours = $66,667 per hour. Change the target or hours only if the plan itself changes.
  3. Download the template if you will import from Excel instead of typing.

2. Before the live (63-day runway tab)

  1. Set "Status as of" to today. The current phase gets a green outline.
  2. Fill each phase's warning-signal inputs when the data arrives: signatures by 23 Oct, stock units by 6 Nov, 11.11 results, weekly teaser views, 5 Dec mismatches.
  3. Tick each control as it is done. Ticks are your evidence for the review.
  4. On 14 Nov, read the go / no-go panel. 11.11 GMV ÷ 11.11 hours ≥ $68,000 keeps Creator B, otherwise switch to Creator E.
  5. Enter 11.11 cancelled GMV in the Prove phase. It becomes the live-day cancellation benchmark.

3. Every hour on 12.12

  1. At :00, read the TikTok Shop LIVE dashboard and copy the cumulative figures for the hour just ended: GMV, orders, views, and cancelled GMV if shown.
  2. Pick "Hour ending" (it moves to the next empty hour by itself), type the numbers, press Save hour or Enter.
  3. Enter every hour. If you skip one, the next entry covers two hours and shows as Unknown, because the 2-hour rule cannot be checked.
  4. Typo? Re-save the same hour to overwrite it, or delete it in the list.

4. Read the screen, top to bottom

Status banner
On pace (last hour passed) · Watch (1 miss) · Act now (2 misses in a row) · Fix data · Target met.
KPI strip
Ordered GMV, gap to the straight-line plan, hours passed, cancel share and net GMV, and the catch-up rate still needed.
Hour by hour
15 cells by shift. Green = hour ≥ $66,667, red = below, grey = pending or unknown. The live shift is outlined.
Next move
The pre-agreed action and its owner. Nothing here is generated: it is the deck's Q3 or Q4 wording.
Three drivers
Which of views, conversion or AOV pulled the last hour below target. The weakest one gets its Q3 action.

5. When a signal fires

  1. Watch (1 of 2): fix the weakest driver this hour and get the shift reset ready.
  2. Act now (2 in a row): bring the next shift reset forward: fresh hero deal (Creator B, Brand rep), ad top-up (TTS Ops), co-host swap (Creator B).
  3. Log it. In the Decision log, enter the time, owner and what was done. The next hours show whether it worked.
  4. Do not stack new ideas mid-live. If the listed action is not enough, the campaign lead decides, and that decision is logged too.

6. Cancellations

  1. Why track them: headline livestream GMV usually counts every order placed. The reported 100 billion VND Quyền Leo Daily session was "total revenue from orders generated during the live, including cancelled and returned orders" (Công Thương, 2024).
  2. What the pass mark uses: ordered GMV, the same basis as the case target. Net GMV is shown next to it so nobody overstates the result.
  3. Benchmark: the 11.11 rehearsal cancel share. Above it shows "Above 11.11". With no 11.11 figure, the tool tracks without colour. The ~30% in the article is one founder's illustrative estimate, not a measured rate, so it is not used as a threshold.
  4. Response when above 11.11 (our rule, from the reason given in the article: buyers cancel and reorder when a better price appears): drop deals on new hero SKUs rather than cutting the price of a SKU already sold earlier in the live, and confirm size and shade in the consult.

7. After the show

  1. Export Excel (Hourly log card). Sheets: hourly results, decision log, runway status, settings.
  2. On 13 Dec, re-enter the 23:00 cancelled GMV once late cancellations settle, then export again for the final net figure.
  3. Review: which hours missed, which driver was weakest, which logged actions were followed by a pass.

Data rules

  • Missing values are never set to zero. Blank cancelled GMV = not tracked for that hour.
  • Counters must not go down, and cancelled GMV cannot exceed ordered GMV. Otherwise the tool shows Fix data and blocks actions.
  • The downloaded HTML file saves data in this browser between refreshes. Use one device and one browser on the day.
  • "Load demo" fills seven made-up hours for training. Clear the day before going live.
